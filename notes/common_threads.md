# Common Threads Across Portfolio References

Patterns, principles, and design decisions that appear in **3 or 4 out of 4** reference portfolios.

---

## 1. Layout — The Holy Trinity Structure

Every portfolio follows the same three-part page structure:

```
┌─────────────────────────┐
│   Nav (minimal)         │
├─────────────────────────┤
│   Hero / Identity       │
│   (name + tagline)      │
├─────────────────────────┤
│   2-Column Project Grid │
│   ┌─────┐  ┌─────┐     │
│   │     │  │     │     │
│   └─────┘  └─────┘     │
│   ┌─────┐  ┌─────┐     │
│   │     │  │     │     │
│   └─────┘  └─────┘     │
├─────────────────────────┤
│   Footer (sign-off)     │
└─────────────────────────┘
```

- **Nav → Hero → 2-Col Grid → Footer**. No exceptions. No sidebars, no multi-section scrolling pages — just this clean vertical flow.
- The **2-column grid** is universal (all 4). Typically **4–6 projects** shown.

---

## 2. Navigation — Radically Minimal

| Pattern | Portfolios |
|---------|-----------|
| Navigation has ≤ 4 links | All 4 |
| Common links: Work, About, Resume | 3 of 4 |
| No dropdowns, no hamburger menus | All 4 |
| Nav is visually quiet — small, light text | All 4 |

> The nav never competes with the hero for attention. It's a utility, not a feature.

---

## 3. Hero — Name Is the Hero

All 4 portfolios use the **designer's name as the primary visual element** of the hero section. No stock photos, no generic illustrations, no carousels.

| Element | Frequency | Notes |
|---------|-----------|-------|
| Large name as hero focal point | 4/4 | Cursive, bold serif, lowercase sans — style varies but name dominance is universal |
| One-line tagline/descriptor | 4/4 | "an empathetic UX designer…", "product designer previously @…", etc. |
| Previous company credentials | 4/4 | Every portfolio name-drops employers (Apple, Google, Meta, NASA, etc.) |
| No headshot in hero | 4/4 | None show a photo of the designer on the homepage |
| No auto-playing video or animation | 4/4 | Static hero in all cases |

> **Key principle**: The hero section establishes *who you are* and *where you've worked* — nothing else. Personality comes through typography, not imagery.

---

## 4. Typography — Deliberate Font Contrast

All portfolios use **intentional typographic contrast** as a design tool, rather than relying on one font for everything:

- **Rebecca**: Hand-drawn cursive name vs. clean sans-serif body
- **Brandon Lee**: Ultra-bold serif name vs. monospaced subtitle vs. sans-serif body
- **Shaahana**: Serif headings + italic serif project titles vs. sans-serif body
- **Michelle Liu**: All sans-serif, but contrast through size and weight

**Common typographic rules**:
- Hero text is **dramatically larger** than everything else (3–5x body size)
- Body text is small and light (~13–14px, gray)
- Project titles use a **distinct style** from body text (bold, italic, or different font)
- Tags/labels are the smallest text on the page (~10–12px)

---

## 5. Color — Restrained Base, Colorful Projects

Every portfolio follows the same color strategy:

```
Page chrome (nav, bg, text, footer) → Neutral / monochrome
Project thumbnails → Where all the color lives
```

| Pattern | Frequency |
|---------|-----------|
| White or near-white page background | 4/4 |
| Near-black primary text | 4/4 |
| Gray secondary text | 4/4 |
| ≤ 1 accent color on page chrome | 4/4 |
| Colorful/varied project thumbnails | 4/4 |

> **Key principle**: The page itself is a neutral canvas. Color is reserved for the project work, which ensures each project's unique visual identity stands out without clashing with the page design.

---

## 6. Project Cards — Visual-First, Description-Light

All project cards prioritize **the image over text**:

| Element | Frequency |
|---------|-----------|
| Large rounded-corner thumbnail | 4/4 |
| Border-radius on thumbnails (~12–16px) | 4/4 |
| No card borders or drop shadows | 4/4 |
| Project title below or on the image | 4/4 |
| Description ≤ 2 lines | 4/4 |
| Shows actual product (phone mockups, UI screenshots) | 4/4 |

**Thumbnail-to-text ratio**: Roughly **75–80% image, 20–25% text** for each card. The image does the heavy lifting.

**Card metadata styles** (varied):
- Pill-shaped tags (Rebecca, Brandon Lee)
- Numbered list (Shaahana)
- Company + year badge (Michelle Liu)

---

## 7. Spacing — Generous Whitespace as a Design Choice

| Pattern | Details |
|---------|---------|
| Wide page margins | 8–15% of viewport width. Content never touches edges. |
| Generous hero padding | Hero takes 20–50% of initial viewport. |
| Consistent grid gutters | 16–32px between project cards. |
| Vertical breathing room | ~32–48px between card rows. |

> Whitespace is used **aggressively** — these aren't dense dashboards. Every element breathes. The space itself communicates confidence and sophistication.

---

## 8. Footer — Warm and Human

Every footer ends with a **personal, conversational touch** rather than a corporate sign-off:

- Rebecca: Contact info + short bio blurb
- Brandon Lee: *"Glad we could cross paths."*
- Shaahana: *"Thanks for coming by!"*
- Michelle Liu: *"Let's work together!"* + social links

All footers include **LinkedIn and email** at minimum. Footers are compact — never more than ~100px tall.

---

## 9. Principles Summary

| Principle | Description |
|-----------|-------------|
| **Identity over decoration** | The hero is about *who you are*, expressed through typography — not stock art or generic visuals |
| **Neutral canvas, colorful work** | Page stays monochrome; project thumbnails carry the color |
| **Visual hierarchy through scale** | Name is huge → tagline is medium → everything else is small |
| **Show, don't tell** | Large product mockup images > lengthy project descriptions |
| **Restraint = sophistication** | Minimal nav, no clutter, generous whitespace, ≤1 accent color |
| **Personality in details** | Warmth lives in the footer sign-off, emoji, hand-drawn touches — not in flashy features |
| **2-column grid is the standard** | Universal layout for project showcases |
| **Credentials up front** | Company affiliations are mentioned within the first 2 lines of the page |
